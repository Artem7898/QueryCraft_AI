# Руководство по QueryCraft AI

[English](README.md) · **Русский**

## Что делает проект

QueryCraft AI превращает описание на русском или английском в черновик запроса к базе данных. Вы описываете нужный результат, выбираете СУБД и уровень сложности, а приложение возвращает текст запроса и краткое пояснение. Черновик можно посмотреть и скопировать в браузере. Перед выполнением в своём инструменте работы с СУБД его нужно сверить с реальной схемой данных.

Проект помогает перейти от вопроса «Какова выручка за каждую неделю?» к запросу, который можно проверить и доработать. Аналитики могут начать с черновика для отчёта, разработчики — подобрать структуру запроса, а учащиеся — сравнить, как одна задача решается в разных диалектах. Пояснение связывает формулировку задачи с фильтрами, объединениями и группировкой в черновике.

## Какие запросы можно получить

| СУБД | Типичная задача |
| --- | --- |
| PostgreSQL | Фильтрация, объединение таблиц, агрегаты и более сложные запросы, например отчёты с группировкой |
| MySQL | Запросы для приложений и отчётов с синтаксисом MySQL |
| SQLite | Запросы к локальным базам, прототипам и небольшим наборам данных |
| MongoDB | Фильтры и конвейеры агрегации для коллекций в синтаксисе оболочки MongoDB |

В форме доступны три уровня сложности: **простой**, **средний** и **продвинутый**. При генерации этот выбор подсказывает модели, насколько сложную структуру запроса использовать. Выбранная СУБД задаёт целевой синтаксис. Элементы формы доступны на русском и английском, на странице есть примеры описаний, а результат подсвечивается. Браузер запоминает выбранный язык и цветовую тему.

## Как выбрать режим

| Режим | Как работает | Для чего подходит |
| --- | --- | --- |
| Генерация моделью (по умолчанию) | API отправляет описание, необязательную схему и инструкции выбранному провайдеру, затем проверяет синтаксис для нужной СУБД. Доступны Bytez, OpenAI и локальный Ollama. | Собственные задачи. Ollama запускает модель на вашей машине без API-ключа. |
| Демонстрационный (включается отдельно) | API выбирает готовый пример для пользователей, заказов или общей задачи. | Знакомство с интерфейсом на готовых примерах. |

В демонстрационном режиме результат берётся из шаблона для выбранной СУБД. Например, описание про пользователей вернёт готовый пример, даже если указать другой возраст или порядок сортировки. Интерфейс помечает такие ответы как демопримеры, а у сгенерированных запросов показывает провайдера и модель.

## Как перейти от вопроса к черновику

1. Откройте форму и опишите нужный результат, включая условия отбора, группировку и порядок сортировки. В поле **Схема данных** можно указать таблицы или коллекции, поля, типы и связи. Предел — 3000 символов.
2. Выберите СУБД и сложность, затем запустите генерацию. В результате будут текст запроса, пояснение, время генерации и имя модели.
3. Сверьте черновик со схемой и ожидаемым результатом. Проверьте названия, условия объединения, границы дат, обработку пустых значений и синтаксис выбранной СУБД.
4. Скопируйте проверенный текст в привычный инструмент. Опробуйте запрос на репрезентативных тестовых данных перед использованием в отчёте или приложении.

### Примеры описаний

| Цель | Что ввести в форму | Настройки |
| --- | --- | --- |
| Просмотреть активных пользователей | «Из `users(id, email, age, status, created_at)` выбери активных пользователей старше 25 лет. Покажи новых первыми, не больше 100 строк». | PostgreSQL, простой |
| Подвести итоги продаж по дням | «По `orders(created_at, amount, status)` посчитай количество завершённых заказов и выручку по календарным дням за последние 30 дней. Покажи последние дни первыми». | MySQL, средний |
| Изучить группы клиентов | «В коллекции `customers` посчитай активных клиентов по странам. Покажи страны с десятью и более активными клиентами и отсортируй по убыванию количества». | MongoDB, средний |

Примеры показывают, как передать сведения о схеме и точно описать ожидаемый результат. Модель использует эти сведения при генерации. В демонстрационном режиме ответы берутся из встроенных шаблонов.

## Что важно знать о результате

Проверка синтаксиса помогает отклонить некорректный ответ до показа в форме. Имена полей, поддержку функций в вашей версии СУБД, права и производительность проверяйте в своей среде. QueryCraft AI использует сведения о схеме из формы, а выполнение запроса и его результаты остаются в ваших инструментах работы с СУБД.

При генерации через Bytez или OpenAI описание и контекст схемы получает выбранный облачный сервис. Если Ollama работает на машине с API, запросы к модели остаются на этой машине. По возможности используйте имена полей и синтетические значения. Учётные данные и персональные записи оставляйте за пределами описания.
