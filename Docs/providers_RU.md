# Провайдеры генерации

[English](providers.md) · **Русский**

Задайте `GENERATION_PROVIDER` на бэкенде. Для смены провайдера перезапустите API. Форма и проверка синтаксиса одинаковы для всех вариантов.

| Провайдер | Значение настройки | Ключ | Модель по умолчанию |
| --- | --- | --- | --- |
| Ollama | `ollama` | Для локального запуска не нужен | `qwen2.5-coder:1.5b` |
| OpenAI | `openai` | `QUERYCRAFT_OPENAI_API_KEY` или `OPENAI_API_KEY` | `gpt-4.1-mini` |
| Bytez | `bytez` (по умолчанию) | `BYTEZ_API_KEY` | `Qwen/Qwen2-7B-Instruct` |

Чтобы выбрать другую модель, задайте `MODEL_NAME`. При смене провайдера уберите прежнее значение, если оно указывает на модель, доступную только у предыдущего сервиса.

## Ollama без API-ключа

Установите Ollama на машине, где работает API QueryCraft. Если сервис ещё не запущен, запустите его командой `ollama serve`. Во втором терминале один раз загрузите модель по умолчанию.

```bash
ollama pull qwen2.5-coder:1.5b
```

Активируйте Python-окружение QueryCraft и запустите API из корня репозитория:

```bash
cd backend
GENERATION_PROVIDER=ollama python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Бэкенд отправляет запросы в OpenAI-совместимый интерфейс Ollama на `http://127.0.0.1:11434/v1/chat/completions`. После загрузки модели генерация на той же машине работает без интернета. Часть ресурсов веб-интерфейса по-прежнему загружается через CDN. Если первый запрос превышает тайм-аут при загрузке модели в память, увеличьте `API_TIMEOUT` до 120 секунд. [Установка Ollama](https://ollama.com/download) · [Совместимость API Ollama](https://docs.ollama.com/api/openai-compatibility)

`OLLAMA_API_URL` задаёт базовый адрес с окончанием `/v1` без `/chat/completions`. Обычный HTTP доступен только на loopback-адресе. Для удалённого Ollama укажите подконтрольный вам адрес HTTPS. Бэкенд отправляет запросы к Ollama без заголовка Authorization.

## OpenAI или Bytez

- Для OpenAI задайте `GENERATION_PROVIDER=openai` и ключ `QUERYCRAFT_OPENAI_API_KEY` или `OPENAI_API_KEY` в окружении сервера. При наличии обеих переменных приоритет у переменной QueryCraft. Запросы идут на `https://api.openai.com/v1/chat/completions`.
- Для Bytez задайте `GENERATION_PROVIDER=bytez` и ключ `BYTEZ_API_KEY` в окружении сервера. Базовый адрес по умолчанию — `https://api.bytez.com/models/v2/openai/v1`.

Храните ключи на сервере. Облачный сервис получает описание и контекст схемы из формы. В управляемой облачной среде разрешите исходящие запросы к выбранному провайдеру и задайте ключ в настройках секретов.

## Как проверить выбранного провайдера

Запустите фронтенд и отправьте новое описание для нужной СУБД. Сгенерированный ответ содержит `source: "live"`, имя провайдера и модель. Каждый запрос обрабатывает настроенный провайдер. Для проверки интерфейса с готовыми примерами явно задайте `GENERATION_MODE=demo`. [Запуск приложения и проверка HTTP API](../README_RU.md#локальный-запуск)
